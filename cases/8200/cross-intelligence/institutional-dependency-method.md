# Institutional Dependency Analysis

## Purpose

This module studies how an intelligence organisation can depend on external institutions, technology providers, infrastructure and regulatory environments.

It deliberately separates institutional evidence from person-level attribution.

## Dependency model

For each documented dependency, record:

1. capability required
2. external dependency
3. first documented date
4. reason for adoption
5. geographic or legal jurisdiction
6. governance mechanism
7. documented change or interruption
8. source quality
9. unresolved questions

## Dependency classes

| Code | Class | Meaning |
|---|---|---|
| D1 | Information | External intelligence or information exchange |
| D2 | Compute | External computing capacity |
| D3 | Storage | External storage capacity |
| D4 | Infrastructure | Physical infrastructure outside the organisation's direct environment |
| D5 | Sovereignty | Alternative or state-controlled infrastructure |
| D6 | Governance | External policy, compliance or service-continuity decisions |

## Analytical sequence

**Requirement → adoption → dependency → jurisdiction → governance → change**

The objective is to reconstruct decisions from public evidence rather than infer classified activity.

## Evidence discipline

A dependency is not automatically:

- operational control;
- command authority;
- personal involvement;
- approval by a particular officer;
- proof of classified capability.

Each of those requires separate evidence.

## Decision archaeology

For every dependency, ask:

- What problem was the organisation trying to solve?
- When did the dependency first become visible?
- What alternatives existed publicly?
- What changed after adoption?
- Who controlled the external resource?
- What happened when the external actor changed policy?
- What documentary residue remained?

## Research boundary

This methodology does not attempt to defeat anonymity, obtain protected information, or infer identities from indirect clues.

The objective is to map **institutional dependencies that are already documented in public sources**.

## Core proposition

The important question is not only:

> Who has the information?

It is also:

> **Who supplies, hosts, governs, or can interrupt the infrastructure required to use it?**
