# Fragmentation Framework

## Purpose

This framework tests whether apparently separate low-level recruitment or tasking events can be linked to the same operational cycle using public evidence.

The objective is not to infer a hidden network from similarity. It is to identify independently observable links and measure how much of the relationship survives removal of the initial attribution.

## Core question

> Can multiple apparently independent micro-tasks be shown, from public evidence, to belong to the same operational cycle?

## Model

`surface -> recruit -> micro-task -> intermediary -> adjacent micro-task -> operational objective`

The model is a hypothesis, not an assumed architecture.

## Observable link classes

| Link | Evidence sought |
|---|---|
| Identity | same publicly attributable actor/account |
| Infrastructure | same channel, domain, account infrastructure or technical artifact |
| Temporal | unusually coherent timing |
| Geographic | documented common location or movement |
| Task | documented common operational purpose |
| Language | distinctive repeated wording or recruitment pattern |
| Financial | independently reported common payment mechanism |
| Intermediary | same documented middle actor |
| Target/objective | independently documented common objective |

Similarity alone is weak evidence. Multiple independent link classes are stronger.

## Fragmentation Index

The index is a research aid, not a probability of attribution.

- **F0 — isolated:** no reliable cross-case link.
- **F1 — thematic:** similar task or recruitment surface only.
- **F2 — linked:** at least one concrete cross-case connection.
- **F3 — corroborated cluster:** two or more independent link classes.
- **F4 — reconstructable cycle:** multiple fragments converge on a documented common operational objective.

F4 does not automatically establish the identity of the controller.

## False-Link Test

Before connecting two fragments, ask:

1. Would the connection survive if the original media attribution were removed?
2. Is there a source independent of the first report?
3. Is the shared feature rare enough to be informative?
4. Could the same feature arise naturally from the platform or environment?
5. Is the relationship temporal, infrastructural, interpersonal, or merely thematic?
6. What evidence would falsify the proposed connection?

## Negative-space rule

Absence of a public link is not evidence that no link exists.

The correct result may therefore be:

> **No public evidence currently sufficient to link the fragments.**

## Reporting

Every cluster should record fragment IDs, source IDs, link classes, contradictions, confidence, alternative explanations, unresolved gaps and date of last verification.

## Safety boundary

This framework is for defensive/public-source analysis. It does not provide instructions for conducting sabotage, recruitment, evasion, targeting or operational tradecraft.
